the existing synthetic PostgreSQL cluster on loopback 55442. No provider key,
retained .env, microphone, employee credentials or real application DB is used.
Ports 5179/5180/8793/9333 must be available for browser fixtures.

Each run needs a unique ID; existing results cannot be overwritten. Use inventory
IDs (for example provider-gate, runtime-jobs, answer-db, browser4) for individual
checks after init. If source changes or a suite fails, preserve the failure and
start a new authoritative run. Existing Phase 5.2/5.3 output variables are aliased
only to the NEW run so their original tests cannot overwrite accepted evidence.

The runner executes all original entrypoints and new delivery.check.ts. It
records human npm commands plus actual Node arguments/cwd/port allowlists. The
simple inventory entryExists field may be false for npm build arguments; actual
recorded production build success is authoritative. Full migration validation
