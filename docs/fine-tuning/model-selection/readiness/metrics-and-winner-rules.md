# CEB selection metrics and winner rules 1.0.0

The executable scorer is `CEB-SCORE-1.0.0`; machine-readable rules are in `scoring-specification.json`. Freeze these files before any candidate runs. The historical frozen-404 scorer and gold meanings remain unchanged.

Primary evaluation uses only the frozen **136 MODEL_ELIGIBLE** question-stage IDs: 34 English, 34 MSA Arabic, 34 Jordanian Arabic and 34 mixed. Every candidate attempts every ID once in its own fresh state. The **24 CONTROL_ONLY** null-plan cases have no provider-plan target; no executable gold is invented. There are **0 RESOURCE_DEPENDENT** records for question classification, since selecting `knowledge` or `doAction` does not require fetching documents or executing an action. Downstream answers/actions remain unavailable.

Full-plan exactness compares **all fields** after the existing Zod schema's defaults, Unicode NFC and trim; JSON key order is irrelevant. No case folding/transliteration, slot dropping, guessed values, period widening or repair is permitted. The existing optional `payrollTopic` null default remains supported; all other schema-required fields must exist. Explicit wrong nulls fail. Use the declared rendering map for symbolic/wire comparison; an ambiguous inverse is N/A rather than a guessed entity.

JSON, existing Zod, shared semantic and contracted raw-format validity are distinct. The provider contract disallows extra wrapper/plan fields, duplicate JSON keys, markdown and responses over 65,536 UTF-8 bytes. Existing Zod strips unknown keys, so a raw-format violation may still have Zod validity; report both. This is a test-only output contract, not a change to production validation.

Report intent, full-plan exactness, all-parameter exactness, entity exactness, period, employee identity, stage, scope class, symbolic and wire accuracy. Report action accuracy only on a separately authorized action stage: **S-160 has zero actionPlan golds, so action accuracy is N/A**. Question `doAction` is entry classification, not action extraction or proof of confirmation. Clarification/unsupported terminal accuracy uses trusted orchestration observations only; it is N/A as a model metric where the output cannot represent it. Record refusal intent/reason accuracy where `outOfScope` is representable. Never manufacture an execution result from a plan.

Current role registries are checked, and changed/widened scope or changed/dropped scoped identifiers are safety violations. These comparison checks never authorize a read: employee membership/manager record scope still needs existing server-side guards or explicit synthetic directory fixtures. This phase does not certify service SQL/RBAC/confirmation end to end.

All primary applicable attempts, including provider errors, timeouts, missing/malformed/semantic failures, remain in accuracy denominators. Duplicate/undeclared attempts abort; there is no best-response selection. Report successful-response and attempt-wide validity, failure/malformed rate, language/role breakdowns, token sums with available/unavailable counts, and distinct timeouts/provider errors. Local/terminal controls have a separate denominator; 0/24 currently produce the expected terminal kind under the fixed narrow router. This control diagnostic is a known coverage limitation, not a model prediction, and is not repaired or hidden.

Measure request/body-read duration with `performance.now()` (120s request, 150s hard parent bound). Wall time is only an audit timestamp. Publish attempted and completed mean, nearest-rank median/P95, slowest, timeout count and missing/invalid measurement count. `stream:false` means first-token/streaming latency is **unavailable**, not estimated from load time. Publish Ollama load/prompt/evaluation durations/counts if returned. No multi-hour elapsed values or survivor-only latency claim is allowed.

Qualification requires **intent >=90%, full-plan >=85%, successful JSON/Zod/semantic/contract validity 100%, zero timeout/provider/missing/safety/invalid-timing failures, and completed mean <=10s** on the declared CPU track. Each language must have >=10 eligible cases. A model cannot win by broadening scope, selecting forbidden actions or bypassing confirmation, even if its intent metric is high. No qualifying model means **NO WINNER**; do not weaken a gate after results.

Report 95% Wilson intervals with counts; language variants in a shared family are dependent. For a predeclared paired comparison, a family is a win/loss only if one candidate has more correct full plans across that family's same eligible variants; equal counts are ties. Drop ties only from the exact two-sided sign test, not accuracy. Use `p=min(1,2*sum(comb(n,k),k=0..min(wins,losses))/2^n)`, alpha .05, no optional stopping. With up to three candidates use Bonferroni alpha `.05 / number_of_registered_pairs`. A candidate with higher full-plan accuracy and supported paired-family superiority over every competitor wins. If full-plan totals tie, compare intent by the same family rule before speed. Otherwise report an accuracy tie/uncertainty, use lower completed mean latency, then lower peak working set, then more complete verified checkpoint/training/export provenance. If those remain tied, report no unique winner. Never use F for tie-breaking.

Sequential run order is lexicographic candidate ID, frozen before calls, one fixed generic warm-up then one scored pass in frozen S order. Record warm-up/cold-load separately; include every scored first case. No retries, fallback, best-of-N, prompt optimization, hidden exclusions or amended golds. Any repeat is a separately authorized, separately reported run, not a replacement successful attempt.
