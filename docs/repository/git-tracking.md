# Git tracking policy

This supplied copy has no discovered Git metadata. Tracking history and the
current Git index must be inspected in the authoritative checkout before any
index cleanup. Do not initialize, replace or rewrite history automatically.

## Track

- Maintained application/tooling source, tests, fixtures and documentation.
- Root workspace manifest and lockfile; package manifests/configuration.
- Runtime Copilot JSONL required by the production loader.
- SQL migrations and Drizzle metadata, including schema snapshots.
- Sanitized environment templates after private review; never real credentials.
- Dataset recipes, provenance, licenses, admission/rejection decisions, hashes,
  benchmark definitions, security evidence and small reviewed result artifacts.
- Immutable artifact retrieval manifests when large assets live elsewhere.
- Native Android source, resources and Gradle wrapper, including its JAR.

## Ignore or keep outside Git

Ignore environment files, tokens, signing keys, uploads, local settings,
dependency installations, model installations, Python/Gradle/browser caches,
generated builds and disposable runtime state. `.env.production.example` is
allowed by filename, but must be reviewed for sanitization before staging.

Do not blanket-ignore JSONL, ZIP, model extensions or snapshot directories:
some are protected datasets, upstream provenance or training handoff evidence.
Recovery archives remain visible until inventoried and securely archived.

`artifacts/` is reserved for new disposable output. Its `evidence/` child is
visible to Git for deliberately reviewed evidence. Fine-tuning evidence logs
are also visible except local review-tool process logs and ignored test state.
Visibility is not permission to publish: review privacy, size and provenance.
Existing evidence is neither moved nor regenerated by this policy.

## Lockfiles and review

The root lockfile governs the npm workspace. Keep the existing frontend lockfile
until supported standalone installation workflows have been evaluated. Do not
regenerate either lockfile as an organizational side effect.

In an authoritative checkout, inspect `git status`, tracked paths and targeted
`git check-ignore -v --no-index` cases. Confirm templates/evidence remain visible
and secret/local paths are ignored, without reading their contents. An ignore
rule does not untrack committed files or remove past secrets. Any history
remediation is a separate authorized task.

Avoid `git add .`; stage an explicit reviewed file list. No secret-bearing files,
raw private HR documents or local browser databases may be staged.
